# Как вносить изменения

## Ветки

| Ветка | Что в ней |
|---|---|
| `main` | только готовые версии; напрямую туда не коммитим |
| `SelfKnowledge` | разработка; все изменения — сюда |

Готовая версия попадает в `main` слиянием из `SelfKnowledge` (лучше через pull request на GitHub), после того как прошли все тесты из [testing.md](testing.md). Версию помечаем тегом, например `v0.1.0`, и записываем в [CHANGELOG.md](../CHANGELOG.md).

## Коммиты

- Один коммит — одно логическое изменение: «тема», «удаление бренда», «тесты», «документация».
- Изменения в `photocraft/` держим отдельно от остального проекта: так их проще переносить на новую версию PhotoCraft (см. [editor.md](editor.md#как-обновить-photocraft-из-исходного-репозитория)).
- Сообщение коммита — по-русски, первая строка коротко отвечает на вопрос «что сделано».

## Правила для кода редактора

В `photocraft/` действуют правила исходного проекта ([`photocraft/AGENTS.md`](../photocraft/AGENTS.md)), главные из них:

- вне тестов нет `unwrap()`, `expect()` и `panic!`: ошибки возвращаются через `Result`;
- цвета и скругления — только из `theme::Tokens`, без жёстко прописанных значений;
- каждое изменение — с тестом;
- изменения интерфейса проверяются снимком (`--example snapshot`);
- перед коммитом — `cargo fmt --all` и тесты затронутых крейтов.

## Дизайн

- Источник правды — макет в Figma ([design-system.md](design-system.md)). Если меняется цвет в Figma, меняется и тема редактора, и наоборот: тест `fude_tokens_are_the_fude_design_system_colours` это проверяет.
- Текст должен проходить WCAG AA, это тоже проверяют тесты.
