# Архитектура FUDE

> Статус: редактор готов (PhotoCraft с темой FUDE). Приложение уроков ещё не написано — ниже его план. Что из этого решено, а что нет, отмечено явно.

## Общая схема

```text
┌──────────────────────────────────────────────┐        JSON-канал команд        ┌───────────────────────────┐
│  Приложение FUDE (Tauri + Rust)              │  ─────────────────────────────▶ │  Редактор PhotoCraft      │
│                                              │   открыть файл, выбрать         │  (отдельный нативный      │
│  интерфейс уроков (webview):                 │   инструмент, ui.set, снимок,   │   процесс, egui + wgpu,   │
│  главная, уроки, достижения, активность,     │   состояние документа           │   тема FUDE Тушь)         │
│  статистика, видеогайд и теория, итог        │  ◀───────────────────────────── │                           │
│                                              │   события: какой инструмент,    │                           │
│  ядро на Rust: уроки, прогресс, статистика,  │   какие слои, что нарисовано    │                           │
│  проверка заданий, подсказки                 │                                 │                           │
└──────────────────────────────────────────────┘                                 └───────────────────────────┘
```

## Почему редактор — отдельный процесс

- PhotoCraft — нативное приложение на egui/wgpu. Его собственные правила ([`photocraft/AGENTS.md`](../photocraft/AGENTS.md)) прямо запрещают оборачивать его в Tauri или webview.
- В PhotoCraft любое действие — команда с идентификатором, и есть JSON-канал управления (`--control <порт>`, протокол описан в [`photocraft/docs/control-protocol.md`](../photocraft/docs/control-protocol.md)). Этим каналом приложение уроков может:
  - открывать файл задания и эталон;
  - переключать инструменты и параметры (например, мягкая кисть, непрозрачность 30%);
  - читать состояние: активный инструмент, слои, параметры;
  - делать снимок холста для автопроверки;
  - менять тему (`ui.set {"theme":"fudeInk"}`).
- Так редактор остаётся полноценным PhotoCraft, а FUDE не зависит от его внутренностей.

## Части приложения уроков (план)

| Часть | Что делает | Статус |
|---|---|---|
| Оболочка | Tauri: окно, меню, запуск редактора | решено (Tauri + Rust), не начато |
| Интерфейс уроков | экраны из макета, дизайн-система FUDE | макет готов, фреймворк для webview не выбран |
| Каталог уроков | категории, уроки, сложность, порядок открытия | структура в макете; формат хранения не выбран |
| Видеогайды | два вида: анимированный ролик с интерфейсом редактора и обычное видео | решено, что нужны оба; способ сборки анимированного гайда не выбран |
| Задание и проверка | шаги задания, автопроверка по состоянию редактора и сравнению с эталоном | в макете; не начато |
| Режим подсказки | выноска с номером шага, кольца «начните здесь», теневая фигура на холсте; учитывается в статистике | в макете; не начато |
| Прогресс и статистика | активность по дням, рост навыков, достижения | в макете; хранение (локально или с учётной записью) не решено |

## Открытые решения

Повторяют [PRODUCT.md](../PRODUCT.md):

- учётные записи и синхронизация или только локальное хранение;
- откуда берётся учебный контент и сколько его;
- как собирать анимированные гайды: записанные команды PhotoCraft, проигрываемые в редакторе, или отрендеренное видео;
- фронтенд-фреймворк внутри Tauri;
- лицензия для собственного кода FUDE.
