# Приложение FUDE

Десктопное приложение на **Tauri 2**: интерфейс на **SvelteKit 3 + Svelte 5 + TypeScript** в webview, бэкенд на Rust поверх ядра [`fude-core`](../core/). Редактор PhotoCraft запускается отдельным процессом и управляется через свой JSON-канал.

## Запуск

Нужны Rust 1.99+, Node.js 20+ и собранный редактор.

```bash
cd photocraft
cargo build --release -p photocraft      # один раз, ~6 минут
cd ../app
npm install
npm run tauri dev                        # приложение с горячей перезагрузкой интерфейса
```

Для запуска кликом есть [`app/run-dev.cmd`](../app/run-dev.cmd): он делает то же самое (и `npm install`, если зависимостей ещё нет) в свёрнутом окне консоли. На него можно сделать ярлык с иконкой `app/src-tauri/icons/icon.ico`. Закрытие окна FUDE останавливает и консоль.

Сборка установщика с редактором внутри (из `app/`, после релизной сборки PhotoCraft):

```bash
npm run tauri build -- --config src-tauri/tauri.bundle.conf.json
```

Готовые `.exe` (NSIS) и `.msi` — в `target/release/bundle/`. Встроенные уроки и `photocraft.exe` кладутся в установщик как ресурсы и после установки лежат рядом с `fude.exe`. Дополнительный конфиг [`tauri.bundle.conf.json`](../app/src-tauri/tauri.bundle.conf.json) нужен, чтобы `tauri dev` не требовал собранного редактора. То же самое на GitHub делает сборка [`build.yml`](../.github/workflows/build.yml) — см. [Сборка на GitHub](#сборка-на-github).

Где приложение ищет PhotoCraft, по порядку:

1. переменная окружения `FUDE_PHOTOCRAFT` — полный путь к `photocraft.exe`;
2. рядом с `fude.exe` (так будет в установщике);
3. `photocraft/target/release/photocraft.exe` в репозитории (разработка).

Если редактора нет, приложение работает, а экран практики показывает «Редактор не запустился» с объяснением.

## Где хранятся данные

Всё локально, в `%APPDATA%\ru.fude.app\`:

| Что | Где |
|---|---|
| прогресс (SQLite) | `fude.db` |
| свои и импортированные уроки | `lessons\` |
| снимки холста попыток (для экрана итога) | `attempts\attempt-<N>.png` |
| токен канала управления редактором | `control.token` (новый при каждом запуске редактора) |

Переменная окружения `FUDE_DATA_DIR` подменяет эту папку целиком — для проверок, которые не должны трогать настоящий прогресс.

## Как идёт практика

1. «К практике в редакторе» → `practice_start`: бэкенд запускает PhotoCraft с `--control 0`, `--control-token-file`, `--automation-read-root <папка урока>` и `--automation-write-root <attempts>`, открывает картинку задания (`app.open`) или создаёт чистый холст, заводит попытку в базе. Порт выбирает сам редактор и сообщает его строкой `photocraft: control server listening on …` в stderr; FUDE читает эту строку и подключается. Раньше FUDE сам искал свободный порт и передавал его, и если порт успевали занять, практика после гайда падала с ошибкой «порт занят». Если редактор сообщает, что канал не открылся, или закрывается при запуске, FUDE сразу показывает причину. Гайд и практика одного урока используют один и тот же запущенный редактор.
2. Каждые 4 секунды (или по «Проверить») — `practice_check`: `ui.inspect`, при необходимости снимок холста `app.save`, затем `fude_core::assess`. Шаги проходятся по порядку и остаются пройденными.
3. «Подсказка» (клавиша F1) — `practice_hint`: подсказка засчитывается один раз на шаг; теневые фигуры рисуются на слое «FUDE · подсказка», после прохождения шага слой удаляется.
4. Когда все шаги пройдены — попытка закрывается: опыт, время, сходство с эталоном, журнал, новые достижения; открывается экран итога.

## Редактор в окне FUDE или отдельно

Редактор можно держать двумя способами — для одного маленького экрана и для двух мониторов:

| Режим | Как выглядит | Как включить |
|---|---|---|
| **В окне FUDE** (по умолчанию) | PhotoCraft занимает окно FUDE под панелью инструментов урока; справа выдвигается панель задания | кнопка «Встроить в окно FUDE» |
| **Отдельным окном** | PhotoCraft — своё окно, FUDE показывает шаги, подсказки и эталон | кнопка «Отдельное окно» |

На практике кнопка «Задание» прячет и показывает панель задания справа, чтобы на маленьком экране отдать холсту всё место. Гайд урока в режиме «в окне» рисует прямо в плеере на странице урока. Выбор запоминается.

Как это устроено. PhotoCraft остаётся отдельным процессом: его правила запрещают оборачивать редактор в webview. На Windows FUDE находит главное окно процесса редактора и делает его дочерним окном своего окна без рамки (`SetParent`, [`window.rs`](../app/src-tauri/src/window.rs) — единственный модуль с `unsafe`). Страница отмечает место под редактор действием `use:editorSlot` ([`editor-slot.ts`](../app/src/lib/editor-slot.ts)); при изменении размеров FUDE передаёт прямоугольник в физических пикселях, и окно редактора двигается вслед. «Отдельное окно» возвращает редактору рамку и прежнее место. Уход со страниц урока закрывает редактор.

Клавиатура. Встроенное окно редактора получает клавиатуру, как только по нему щёлкают мышью или пером: окно FUDE ловит нажатие в дочернем окне (`WM_PARENTNOTIFY`) и передаёт фокус редактору. Поэтому все горячие клавиши PhotoCraft работают и внутри FUDE, в том числе H («Рука»). Подсказка FUDE поэтому висит на F1: эта клавиша свободна в PhotoCraft. Пока открыт экран практики и окно FUDE активно, F1 зарегистрирована как горячая клавиша (`RegisterHotKey`), так что она работает и когда фокус внутри редактора. Проверка задания — Ctrl+Enter. Окном редактора считается только настоящее окно приложения: служебное невидимое окно winit (`Winit Thread Event Target`, прозрачное окно-инструмент) отбрасывается. Раньше иногда встраивалось именно оно, а сам редактор оставался отдельным окном без клавиатуры.

На macOS и Linux встраивание пока не поддерживается: там редактор всегда открывается отдельным окном, а кнопки режима не показываются.

## Опыт, ранги, навыки

- Опыт за задание: `40 + 20 × сложность`, без подсказок ×1,5, повторное прохождение — четверть.
- Ранги: 10 кю (0 XP) … 1 кю (3150 XP), 1 дан (3800 XP).
- Навык: каждый пройденный урок даёт своим сторонам навыка `10 × сложность` очков (×1,5 без подсказок); шкала 0–100 — доля от всего, что дают уроки библиотеки.
- Самостоятельность — доля заданий без подсказок.
- Серия — дни подряд с хотя бы одним выполненным заданием; вчерашний день держит серию до конца сегодняшнего.
- Достижения считаются только из настоящих данных ученика. «Редкость среди учеников» из макета не показывается: других учеников у локального приложения нет.

## Код

```text
app/
├── src/                     интерфейс (SvelteKit)
│   ├── lib/api.ts           типы и вызовы команд бэкенда
│   ├── lib/ink.ts           мазок, энсо и горы, нарисованные кодом
│   ├── lib/format.ts        русские числа, падежи, даты
│   ├── lib/checks.ts        виды проверок для редактора урока
│   ├── lib/shortcuts.ts     клавиши практики: F1 подсказка, Ctrl+Enter проверка
│   ├── lib/editor-slot.ts   место под встроенный редактор, выбор режима
│   ├── lib/components/      боковая панель, заставка, печать, сложность, выбор области…
│   └── routes/              экраны
└── src-tauri/               бэкенд (Rust)
    ├── src/db.rs            SQLite: профиль, попытки, шаги, журнал, достижения
    ├── src/progress.rs      опыт, ранги, серии, навыки, достижения
    ├── src/editor.rs        запуск PhotoCraft и клиент канала управления
    ├── src/window.rs        встраивание окна редактора в окно FUDE (Windows)
    ├── src/practice.rs      попытка: проверка, подсказки, итог
    ├── src/learn.rs         команды каталога, урока и разделов прогресса
    ├── src/play.rs          команды гайда и практики
    ├── src/studio.rs        команды мастерской и пакетов
    └── tests/real_editor.rs все гайды в настоящем PhotoCraft
```

## Тесты

```bash
cargo test -p fude-app                                        # бэкенд, 45 тестов (с поддельным редактором)
cargo test -p fude-app --test real_editor -- --ignored        # 12 гайдов в настоящем PhotoCraft
cd app && npm test                                            # интерфейс, 35 тестов
cd app && npm run check                                       # типы Svelte и TypeScript
```

## Сборка на GitHub

В `.github/workflows/` два сценария GitHub Actions; оба идут на `windows-latest`:

| Сценарий | Когда | Что делает |
|---|---|---|
| [`ci.yml`](../.github/workflows/ci.yml) | каждый push в `main` и `SelfKnowledge`, каждый pull request | `npm run check`, тесты интерфейса, сборка интерфейса, `cargo fmt --check`, clippy с `-D warnings`, `cargo test --workspace` |
| [`build.yml`](../.github/workflows/build.yml) | push в `main`, теги `v*`, вручную (Actions → Build → Run workflow) | собирает PhotoCraft в релизе и установщики FUDE с редактором внутри; выкладывает артефакт `FUDE-windows-x64`: установщики `.exe` и `.msi` плюс переносная версия `FUDE-portable-windows-x64.zip` (`fude.exe`, `photocraft.exe`, `lessons/`) |

Тег вида `v0.1.0` дополнительно создаёт релиз на GitHub с этими файлами:

```bash
git tag v0.1.0
git push origin v0.1.0
```
